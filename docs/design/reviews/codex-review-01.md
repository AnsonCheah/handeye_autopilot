The package split and single action are sensible. **`GetPositionIK` is a sound MoveIt-backed candidate filter**, provided its limitations become explicit contracts.

- **BLOCKER — IK state and collision semantics (§1.1).** Require an SRDF `group_name` and model-known `ik_link_name` rigidly connected to the solver tip; a TCP existing only in TF needs pose conversion. Define whether requests use MoveIt’s monitored state or explicit seeds. Joint-only seeds need `robot_state.is_diff=true`; otherwise conversion can clear attached collision bodies. A vendor implementation must honour `avoid_collisions`, not merely serve the same message type. [IK contract](https://raw.githubusercontent.com/moveit/moveit_msgs/ros2/msg/PositionIKRequest.msg), [state conversion](https://raw.githubusercontent.com/moveit/moveit2/jazzy/moveit_core/robot_state/src/conversions.cpp).

- **BLOCKER — Cancellation requires implementation (§4–5).** rclpy’s default action server **rejects cancellation**. Specify asynchronous clients, callback groups/executor scheduling that keep TF, images and cancellation responsive, and a cancellation state machine that cancels the active `MoveGroup` goal and waits for its terminal outcome. A client timeout or cancellation acknowledgement does not establish that motion stopped. Test cancellation during motion and capture. [rclpy server](https://raw.githubusercontent.com/ros2/rclpy/jazzy/rclpy/rclpy/action/server.py), [client](https://raw.githubusercontent.com/ros2/rclpy/jazzy/rclpy/rclpy/action/client.py).

- **BLOCKER — Capture timing is underspecified (§5–6).** Require fresh measured robot updates, a common timestamp domain, consistent `use_sim_time`, and image acquisition stamps after settling. Pair **every consensus frame** with TF at its own stamp. Wait asynchronously for delayed TF with a deadline; never substitute latest TF. `message_filters` synchronises image/info, not robot measurements or hardware clocks. Add delayed-TF, frozen-state and clock-reset tests. [TF buffer API](https://raw.githubusercontent.com/ros2/geometry2/jazzy/tf2_ros_py/tf2_ros/buffer.py).

- **BLOCKER — Camera subtree ownership (§7).** State the composition explicitly: `T_parent_root = T_parent_optical × inverse(T_root_optical)`. Require a rigid root-to-optical chain and exactly one publisher owning the root’s external attachment. An existing URDF mounting joint, driver tracking transform or previous calibration can still conflict. Refuse duplicate attachments/cycles. Depth follows correctly only when the driver’s internal extrinsics are valid.

- **SHOULD-FIX — IK budgets, batching and rejection reasons (§1.2).** Use bounded one-candidate requests: `pose_stamped_vector` represents simultaneous end effectors, not a candidate batch. Bound retries and outstanding calls; `NO_IK_SOLUTION` does not distinguish collision from unsuccessful search. Crucially, the inspected Jazzy implementation passes only `timeout.sec`, dropping nanoseconds; verify the installed version and document the server default-timeout workaround. A client deadline does not cancel server computation. [Jazzy implementation](https://raw.githubusercontent.com/moveit/moveit2/jazzy/moveit_ros/move_group/src/default_capabilities/kinematics_service_capability.cpp).

- **SHOULD-FIX — Make the MoveGroup request concrete (§5).** Specify position/orientation constraints and tolerances, or joint constraints from the selected IK solution; finite planning time; and **both** velocity and acceleration scaling in `(0,1]`—zero defaults to full scaling. Check goal acceptance, terminal status, MoveIt error code and measured target attainment: a planning-only server can return success without moving. Apply the box as `path_constraints` if it must constrain intermediate motion. [Request](https://raw.githubusercontent.com/moveit/moveit_msgs/ros2/msg/MotionPlanRequest.msg), [execution implementation](https://raw.githubusercontent.com/moveit/moveit2/jazzy/moveit_ros/move_group/src/default_capabilities/move_action_capability.cpp).

- **SHOULD-FIX — Keep one action; define its semantics (§4).** Reject concurrent runs and invalid mode/profile values; snapshot configuration per goal. Define `SUCCEEDED` versus quality `passed=false`, runtime `ABORTED`, and `CANCELED`. Add an error code and explicit transform-validity indicator. Define whether `~/capture` acknowledges a queued capture or an accepted observation, and reject it outside the manual capture phase.

- **SHOULD-FIX — Raw and rectified images need different geometry (§6).** Use raw `K,D` versus rectified `P` with zero distortion, account for rectification `R`, ROI/binning, and reject unsupported distortion models or uncalibrated intrinsics. Reuse `cv_bridge` and `image_geometry`. Specify compatible sensor QoS, synchroniser policy, and handling of cached/static `CameraInfo`. [CameraInfo contract](https://raw.githubusercontent.com/ros2/common_interfaces/jazzy/sensor_msgs/msg/CameraInfo.msg).

- **SHOULD-FIX — Make installation part of the architecture (§3,9).** `ament_python` with `PKG.core` is fine. Use recursive package discovery, ROS-free parent `__init__.py`, installed launch/config/resource files, and proper rosidl generator/runtime/interface-group declarations. Declare system dependencies through `package.xml`/rosdep, including `python3-opencv`, NumPy and SciPy. Keep demo dependencies separate and test a normal installed build on each distro’s supported OS. [Packaging](https://github.com/ros2/ros2_documentation/blob/rolling/source/Developer-Tools/Build/Developing-a-ROS-2-Package.rst), [rosdep mappings](https://raw.githubusercontent.com/ros/rosdistro/master/rosdep/python.yaml).

- **SHOULD-FIX — Expand the OpenCV compatibility contract (§2,10).** Ubuntu [24.04](https://packages.ubuntu.com/noble/python3-opencv) and [26.04](https://packages.ubuntu.com/resolute/python3-opencv) currently ship 4.6 and 4.10. Cover legacy detection, board construction and `draw`/`generateImage`, plus board-coordinate and pattern changes. Test identical fixed board fixtures across versions; matching API calls alone is insufficient. Use distro packages in CI. [OpenCV compatibility notes](https://docs.opencv.org/4.12.0/df/d4a/tutorial_charuco_detection.html).

- **SHOULD-FIX — Explain visibility bootstrapping (§1.2,5).** One seed detection cannot determine both unknown rigid transforms. Require an initial estimate or a multi-pose bootstrap before enforcing predicted visibility. Add OpenCV PnP/IPPE to the reuse map and explicit transform-direction tests for both calibration modes.

- **SHOULD-FIX — Correct the ecosystem claims (§2).** Compare against [easy_handeye2](https://github.com/marcoesposito1988/easy_handeye2), [industrial_calibration_ros2](https://github.com/ros-industrial/industrial_calibration_ros2) and the rclpy wrapper [pymoveit2](https://github.com/AndrejOrsula/pymoveit2). Document which components are reusable and why others do not meet the package’s constraints; remove blanket “do not exist” claims.

- **NIT — Attachment warning (§1.1).** URDF collision geometry is not an attached collision object. Recognise both representations before warning.

- **NIT — Namespaces (§1.1).** Default to relative endpoint names (`compute_ik`, `move_action`), retaining parameters/remapping.

- **NIT — Synthetic camera (§2,9).** Keep the lightweight homography generator for deterministic tests, but remove the claim that camera simulation is unavailable: Gazebo with `ros_gz` already provides camera streams. Describe homography-test limitations explicitly. [Gazebo camera integration](https://gazebosim.org/docs/ionic/migrating_gazebo_classic_ros2_packages/).
