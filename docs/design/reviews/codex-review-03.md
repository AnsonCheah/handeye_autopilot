03 broadly follows 01/02, but its release gates and early dependencies need tightening.

- **BLOCKER — M0/M6: make dependency resolution an explicit gate.** “Checked in M0” currently has no corresponding acceptance criterion. Require clean-container `rosdep install` on each target OS, covering runtime, interface, launch, demo and test dependencies. A key resolving through pip is insufficient for a farm release. `pymoveit2` has release entries in [Jazzy](https://github.com/ros/rosdistro/blob/master/jazzy/distribution.yaml), [Lyrical](https://github.com/ros/rosdistro/blob/master/lyrical/distribution.yaml) and [Rolling](https://github.com/ros/rosdistro/blob/master/rolling/distribution.yaml); verify binary availability and API compatibility. [Dependency policy](https://github.com/ros/rosdistro/blob/master/REVIEW_GUIDELINES.md).

- **BLOCKER — M6: start release administration earlier.** Add source indexing/name review, release-team access and a separate release repository during M0/M1. Rolling requires hosting that repository under `ros2-gbp`. Then configure separate bloom tracks and submit release PRs for each distro. Starting everything in M6 leaves external approvals on the critical path. [Official procedure](https://github.com/ros2/ros2_documentation/blob/rolling/source/Developer-Tools/Build/Releasing/Release-Team-Repository.rst).

- **BLOCKER — M6: completion does not establish the promised release.** Replace the Jazzy-only apt check with successful farm builds and clean binary installation of all three packages on **all three distros**, followed by interface-import and launch smoke tests. Distinguish availability in `ros-testing` from public availability after synchronization; syncs typically add a two-to-four-week cycle. [Release stages](https://github.com/ros2/ros2_documentation/blob/rolling/source/Developer-Tools/Build/Releasing/_Next-Steps.rst).

- **SHOULD-FIX — ordering: allow early integration probes.** Relax “nothing is started” to permit a camera/TF capture slice and actual MoveIt plan/execute/cancel probe before completing M2. Collect real board images during M1 and reserve arm access in M0. Otherwise detector tuning and middleware assumptions remain untested until expensive downstream work is complete.

- **SHOULD-FIX — M0: finish package identity and release metadata.** Choose collision-free, lowercase final names before interface generation. Require real maintainer names/emails, license metadata, matching `package.xml`/`setup.py` versions, numeric `MAJOR.MINOR.PATCH` versions, immutable release tags, and **one `CHANGELOG.rst` per package**. Keep `_interfaces` separate, verify generator/runtime and referenced-message dependencies, and release it alongside the other packages. [Manifest requirements](https://github.com/ros-infrastructure/rep/blob/master/rep-0149.rst), [release preparation](https://github.com/ros2/ros2_documentation/blob/rolling/source/Developer-Tools/Build/Releasing/First-Time-Release.rst).

- **SHOULD-FIX — M0: strengthen acceptance and delay interface freeze.** Add a downstream Python client that imports and constructs the installed action/message types. Freeze interfaces after M3 exercises them. The literal test command should include `--return-code-on-test-failure` and `colcon test-result --verbose`; plain `colcon test` can return success despite failed tests. [Colcon behavior](https://colcon.readthedocs.io/en/released/reference/verb/test.html).

- **SHOULD-FIX — M1–M5: replace ambiguous success criteria.** Commit sweep seeds/ranges, translation/rotation tolerances and expected rejection codes; test observation-save/re-solve round trips. Give session tests deadlines and independent result assertions. Define M5’s required dataset, configuration, held-out error and repeated-run evidence; “one documented run” accepts arbitrarily poor results. Preserve 02’s distinction between stability and accuracy.

- **SHOULD-FIX — M4: explicitly schedule the promised failure tests.** Before hardware, require tests for planning-only success, collision rejection, cancellation without terminal completion, and retained attached objects. Stub IK tests cannot verify distro-specific server behavior: add actual `compute_ik` contract checks across all three, as 01 requires.

- **SHOULD-FIX — estimates/scope: treat 16 weeks as optimistic.** Specify hours/week and estimate effort separately from hardware access, reviewer and sync waits; recalibrate after M1. Split the oversized M1 into smaller deliverables. Defer the second robot demo, live verification and interactive box editing; retain configured bounds, collision checks and cancellation. Reflect agreed cuts in 01/02.

- **NIT — completeness:** assign milestones and acceptance checks for board printouts, bag recording, `ruff`/`mypy`, and the missing learning topics. Replace “if cheap” with an explicit backlog decision.
